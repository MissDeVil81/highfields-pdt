Required Live login system

1. An Admin creates a user.
2. Every user has:
    * Full name
    * Work email address
    * Role(s)
    * Reports To
    * Team membership
    * Active/inactive status
    * Probation status where applicable
3. The user’s work email address is their login username.
4. When a user is created, the system generates a temporary password which the Admin can give them.
5. The user logs in with their email address and temporary password.
6. On first login they MUST be forced to create their own password.
7. Once changed, the Admin cannot see the user’s chosen password.
8. If they forget their password, the Admin Portal has a Reset Password / Generate New Temporary Password function.
9. This generates a new temporary password for the Admin to give the user and sets must_change_password to true.
10. The user logs in with the new temporary password and is forced to create their own password again.
11. Inactive users cannot log in.
12. Users are deactivated rather than deleted so their historical records remain intact.

Environments

* Development: no login required.
* Demo: no login required and we can switch between user types.
* Live: authentication required using the process above.
